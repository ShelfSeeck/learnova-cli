# PDF 转知识参考型 Skill：构建设计

> 状态：设计已确认，待实现。本文描述新构建模块的目标行为，不代表现有 CLI 已具备这些能力。
> 确认日期：2026-10-31。

## 1. 定位与范围

在 Learnova CLI 中增加面向 agent 的文档构建模块，将 PDF 的解析内容组织成可按需查阅的知识参考型 Skill。

| 术语 | 定义 |
|---|---|
| 知识参考型 Skill | 由知识索引、原文切片、相关图片和来源记录组成，供 agent 定位和读取文档知识 |
| 构建任务 | 围绕一份输入文档及其构建配置形成的、可保存进度并继续执行的处理过程 |
| 本地构建 Skill | 由文档构建任务生成、尚未作为社区版本安装的 Skill |
| 社区安装 Skill | 经 Learnova 社区分发链路下载并安装的 Skill |

模块借鉴 [pdf2skill](https://github.com/CutePigdaddy/pdf2skill) 的解析、语义切片和索引生成思路，按 Learnova CLI 的分层重新组织。

- 首版生成知识参考型 Skill。方法流程型等其他类型，由宿主 agent 借助外部指导或能力处理；CLI 明确说明当前能力边界。
- 主要输入为 PDF；解析后的 Markdown 是后续阶段的标准输入，也允许从已有 Markdown 开始。
- PDF 解析支持远程和本地部署的 MinerU 服务；本地模式仍需要可用的解析服务。
- 不迁入 Web 界面、浏览器 SDK、OPFS 存储或浏览器代理服务。
- 首版提供发布引导，不打通登录、上传、提交审核和状态查询。

## 2. agent 使用流程

1. 确认输入文档和项目目录。默认使用宿主 agent 推进任务。
2. 优先询问输出位置。用户未指定时，使用项目内 `.agents/skills/<skill-name>/`；agent 知道自己的实际加载目录时，可以显式配置或覆盖。
3. 检查解析方式。显式参数优先于已保存配置；没有有效配置时，由 agent 询问使用远程还是本地服务，并允许保存选择。
4. 创建构建任务，解析 PDF，保存 Markdown、图片和来源信息。已有 Markdown 可直接进入下一阶段。
5. agent 读取文档结构及必要片段，提交切片方案；脚本校验方案，按原文裁切。
6. agent 提供简介、关键词和导航内容；脚本组织参考文件、索引与来源记录。
7. 完成完整性校验后，将成品放入目标 Skill 目录，返回路径、构建状态和提示信息。
8. 用户明确提出发布需求时，提供打包和发布步骤引导。

CLI 默认非交互。询问由宿主 agent 完成，脚本接收明确参数并返回结构化结果；缺少必要配置时返回可处理的问题，不在终端阻塞等待输入。

项目目录由调用方明确提供；没有提供时，以调用工作目录为根。不能假定脚本所在目录就是用户项目，也不能把用户级工具目录的存在当作当前宿主 agent 的身份。

## 3. 运行模式

| 模式 | 判断与推进方式 | 模型配置 |
|---|---|---|
| 宿主 agent 模式，默认 | agent 决定语义切片和索引内容，CLI 校验并执行文件处理 | 复用宿主 agent 的判断能力，CLI 无需另配 LLM 密钥 |
| 自动模式 | 脚本调用用户配置的模型，完成相同的判断任务和流水线 | 用户提供可用的模型服务配置 |

两种模式共用阶段、任务状态、判断结果格式和校验逻辑。宿主 agent 模式通过结构化输入、结果提交和继续执行接口推进，不假定 CLI 可以直接调用宿主模型。

| 阶段 | 输入 | 输出 |
|---|---|---|
| 解析 | PDF 和解析配置，或已有 Markdown | 标准 Markdown、图片与原始来源信息 |
| 切片 | 文档结构、原文和切片方案 | 原文切片、层级关系与准确的来源范围 |
| 索引生成 | 切片与语义描述 | `SKILL.md`、参考文件和来源记录 |
| 校验与落盘 | 候选 Skill | 校验结果与正式 Skill 目录 |

- 首版支持按阶段执行、暂停、查看进度和从指定阶段继续。
- 允许显式切换运行模式，接着同一个任务继续；已完成且有效的结果不重复生成。
- 改变输入、配置或切片方案时，失效对应阶段及其下游结果。
- 不在失败后静默切换模型或运行模式。
- 各阶段独立选择模型或服务是后续能力。首版自动模式使用统一模型配置，解析器单独配置。

分层保持命令薄、逻辑集中：命令层只解释参数和返回结果；构建服务协调阶段；`core/` 放标题、范围、切片、校验等纯逻辑；解析和模型调用由适配层承接。网络调用沿用统一网络边界，状态采用原子写入。

构建服务统一管理任务文件和候选产物，正式目录替换复用安装引擎的事务方式。实现前须同步架构文档中的文件操作边界。文档解析不并入服务社区 `search/info/fetch` 的 `SkillSource` 协议。

## 4. 产物与目录

```text
<project>/
├── .learnova/
│   └── builds/<task-id>/       # 解析全文、图片、方案、阶段结果与断点
└── .agents/
    └── skills/<skill-name>/   # 通过校验后可加载的成品
        ├── SKILL.md
        ├── references/        # 原文切片及其使用的图片
        └── .learnova-build.json
```

- `.agents/skills/` 是统一默认位置，不根据检测到的 agent 自动改成其他目录；显式输出配置优先。
- 默认使用项目级位置，通常不放用户级 Skill 目录。构建默认值独立于现有安装命令的默认层级。
- 目标已存在时默认报告冲突，显式要求覆盖才替换。失败不得损坏已有 Skill。
- 构建工作目录默认不纳入版本库。未完成产物留在任务目录，不作为正式 Skill 加载。
- 最终 Skill 包含索引、完整覆盖解析内容的原文切片、相关图片和来源记录。
- 原 PDF 保留原位置；完整解析全文和阶段文件留在构建工作目录，不默认打包进成品。
- 来源记录应包含本地构建标记、输入指纹及参考文件对应的原文范围；可获得的页码信息一并保留，不推测缺失页码。
- 来源记录不得包含密钥、本机绝对路径或其他不应随 Skill 分发的环境信息。

`.learnova-build.json` 为本设计采用的构建来源文件；具体字段及版本在实施规格中定义。配置、凭证仍走现有配置边界，构建任务只保存必要的配置引用，不复制密钥。

## 5. 完整性与恢复

### 内容完整性

- 完整保留解析结果，包括目录、附录、习题、答案和图片。不默认概括、删减或自动清理正文。
- 原文切片由确定性裁切产生；模型生成的简介和关键词与原文内容分开保存。
- 校验切片范围的连续性和覆盖关系，确保没有未声明的遗漏或重复。必要的文本规范化必须可追溯。
- 切片方案必须校验边界、顺序、范围和不可拆单元；无效方案返回纠正，不靠猜测执行。
- 代码、表格、完整证明等不可拆单元超过目标大小时，保留完整并标注超大块，允许 agent 按范围读取。
- 块大小是软目标，内容完整是硬要求；不能为了满足大小阈值丢失内容。
- 每个子块记录自己的实际原文范围，不能沿用父块的完整范围。
- `SKILL.md` 的参考链接和切片中的本地图片链接必须可解析，不留下缺失文件。

这里的完整性以解析结果为基准。解析服务本身的识别准确性不由结构校验保证；内容问答抽检另设可选验证步骤。

### 任务恢复

- 任务记录输入指纹、有效配置、阶段状态及产物引用。方案或相关生成规则变化时，重新判定缓存有效性。
- 检查断点对应文件实际存在且有效；不能只凭“阶段完成”标记跳过。
- 阶段失败保留已完成进度，返回错误位置和下一步所需输入。
- 断点原子写入；同一任务避免并发写入。重跑上游时使下游索引和语义缓存失效。
- 宿主 agent 与自动模式使用同一份任务状态；切换执行者不改变原文、切片标识和有效结果。
- 完整性校验未通过时，不把候选产物放入正式 Skill 目录；超大块等已允许情况作为提示返回。

## 6. 管理与发布

### 本地管理

沿用现有的目录扫描方式，不引入独立安装清单或数据库。

| 能力 | 本地构建产物的约定 |
|---|---|
| 列出 | 项目级 `list` 能识别，并显示本地构建来源；扫描仍包含其他来源的有效 Skill |
| 卸载 | 可显式卸载最终 Skill；不连带删除原 PDF 和构建任务 |
| 更新 | 通过重新构建更新，沿用任务恢复和冲突处理规则 |
| 社区升级 | 跳过本地构建产物，不能按同名社区条目覆盖 |

现有 `list`、`uninstall`、`upgrade` 默认操作用户级目录，`--project` 才操作当前项目级目录；本设计不顺带修改这些默认值。

项目级管理必须覆盖统一默认的 `.agents/skills/`，并合并所选 agent 的项目 Skill 根目录，对同一物理目录去重。不能因宿主使用其他目录而漏掉默认构建产物。自定义输出目录需要相应目录适配或显式配置，不递归搜索任意项目路径。

当前社区安装元数据只有目录名和版本，升级尚未检查来源。实施时需要补齐来源识别，并兼容现有安装记录。本地构建产物不能仅凭与社区同名而升级，也不需要虚构社区版本号。旧安装记录和未声明来源的第三方包的兼容细则，在实施规格中明确。

内容的构建历史与当前副本的安装来源应区分。同一 Skill 后续经社区安装时，可按社区安装来源管理，同时保留文档构建的来源记录。

### 发布引导

- 构建成功默认不发布、不上传。
- 用户主动要求发布后，提供可发布目录或压缩包，并引导用户通过可用渠道完成发布。
- 明确说明首版 CLI 尚未打通发布链路，不把引导完成描述成发布成功，也不调用尚未实现的命令冒充提交。

## 7. 首版验收

基础 CLI 保持 Python 标准库运行。文档构建允许按需安装可选依赖，依赖缺失只影响相关构建能力，不影响已有检索和安装；Python 依赖按项目约定使用 `uv` 管理。测试继续沿用现有 `unittest` 体系。

| 验收项 | 通过条件 |
|---|---|
| 能力说明 | 清楚标注只构建知识参考型 Skill，其他类型由 agent 借助外部能力处理 |
| 双运行模式 | 默认宿主 agent 推进；配置模型后可自动运行，且可显式切换后续跑同一任务 |
| 解析方式 | 远程和本地服务可配置；缺少有效配置时交由 agent 确认 |
| 分阶段执行 | 能查看、执行和恢复指定阶段；不要求首版实现各阶段独立模型配置 |
| 输出位置 | 默认项目 `.agents/skills/<skill-name>/`，显式路径可覆盖，不依赖用户级工具检测 |
| 原文完整 | 切片覆盖解析内容、来源范围准确、不可拆超大块保留并标注 |
| 结构校验 | 元数据有效，参考文件和图片链接存在，失败不暴露不完整成品 |
| 恢复与覆盖 | 断点及文件一致，上游变化使下游失效，失败不损坏已有 Skill |
| 本地管理 | 扫描能识别构建来源，支持显式卸载，社区升级跳过本地产物 |
| 发布引导 | 默认不上传；用户要求时提供打包和引导，明确发布尚未集成 |

内容问答抽检是可选验证，不作为每次构建的强制成功条件。各阶段独立模型配置、其他类型 Skill 的专门构建、完整账号与发布链路不在首版范围。

- [cli-spec.md](cli-spec.md)：构建流程、输出默认值、配置和管理行为。
- [architecture.md](architecture.md)：共享任务、阶段接口、模型适配和文件操作边界。
- [maintenance.md](maintenance.md)：新命令维护、错误码与验证要求。

- `skills/learnova-cli/SKILL.md` 及其运行时参考文件：功能实现后再加入 agent 使用指引。
