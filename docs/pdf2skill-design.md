# PDF 转知识参考型 Skill：构建设计

> 状态：本地构建与解析适配已实现，自动模式支持配置的兼容模型服务；真实服务认证验收尚未完成。具体命令与接口以 CLI 规范和运行指南为准。
> 确认日期：2026-10-31。

## 1. 定位与范围

在 Learnova CLI 中增加面向 agent 的文档构建模块，将 PDF 的解析内容组织成可按需查阅的知识参考型 Skill。

| 术语 | 定义 |
|---|---|
| 知识参考型 Skill | 由知识索引、原文切片、相关图片和来源记录组成，供 agent 定位和读取文档知识 |
| 构建任务 | 围绕一份输入文档及其构建配置形成的、可保存进度并继续执行的处理过程 |
| 本地构建 Skill | 由文档构建任务生成、尚未作为社区版本安装的 Skill |
| 社区安装 Skill | 经 Learnova 社区分发链路下载并安装的 Skill |

模块借鉴 [pdf2skill](https://github.com/CutePigdaddy/pdf2skill) 的解析、语义切片和索引生成思路，按 Learnova CLI 的分层重新组织。

- 首版生成知识参考型 Skill。方法流程型等其他类型，由宿主 agent 借助外部指导或能力处理；CLI 明确说明当前能力边界。
- 主要输入为 PDF；解析后的 Markdown 是后续阶段的标准输入，也允许从已有 Markdown 开始。
- PDF 解析支持远程和本地部署的 MinerU 服务；本地模式仍需要可用的解析服务。
- 不迁入 Web 界面、浏览器 SDK、OPFS 存储或浏览器代理服务。
- 首版提供发布引导，不打通登录、上传、提交审核和状态查询。

### 上游机制与迁移取舍

参考代码基线为 pdf2skill 的 `3738467`。保留处理思路，按职责拆分代码，不整体复制应用框架。

| 上游位置 | 真实机制 | 迁入方式 |
|---|---|---|
| `main.py` | 串联解析、章节粗切、递归细分和索引生成 | 保留处理链路；由共享任务编排协调两种运行模式，将成品校验独立为最后一步 |
| `core/pdf_processor.py` | 远程 MinerU 上传、轮询、下载；本地调用 Gradio；PDF 库负责超页数拆分 | 保留解析适配、拆页及图片归集；拆页库和 Gradio 客户端作为可选依赖，配置与进度输出接入 CLI |
| `core/llm_chunker.py` | 提取标题和行号，让模型选择章节切点，再裁切原文 | 保留“结构→方案→裁切”；模型判断改为可提交、可校验的阶段结果 |
| `core/tree_merger.py` | 用树记录层级，递归细分大块，合并小块；以原文锚点定位边界 | 保留层级和递归细分；优先用脚本生成的边界编号定位，减少对模糊字符串匹配的依赖 |
| `core/skill_engine.py` | 叶子块原文写入参考文件，生成关键词、简介和 `SKILL.md` | 保留索引加原文参考的形式；语义描述与原文分开，补足覆盖、引用和图片校验 |
| `utils/checkpoint.py` | JSON 断点、阶段重置、临时文件加原子替换 | 保留原子写入思路；统一任务状态，增加输入与配置指纹及下游失效规则 |
| 配置、引导和展示代码 | 全局配置、首次运行向导、终端进度、Web 与浏览器存储 | 使用 CLI 配置和结构化输出；agent 负责询问，不迁入前端和浏览器存储 |

上游有三处不应直接沿用：`atomic_ranges` 虽被返回却未参与粗切校验；细分子块沿用父块行号；关键词仅取每块前 2,000 字符，可能遗漏后文主题。新实现分别通过保护区间校验、来源范围重算和按需读取更多片段处理。

上游实际细分提示词内联在 `recursive_peel()`，不能把仓内的 `peeling_strategy.txt` 当成当前执行依据。迁入时统一维护有效的判断说明，宿主 agent 与自动模式使用相同的结果约束。

## 2. agent 使用流程

1. 确认输入文档和项目目录。默认使用宿主 agent 推进任务。
2. 优先询问输出位置。用户未指定时，使用项目内 `.agents/skills/<skill-name>/`；agent 知道自己的实际加载目录时，可以显式配置或覆盖。
3. 检查解析方式。显式参数优先于已保存配置；没有有效配置时，由 agent 询问使用远程还是本地服务，并允许保存选择。
4. 创建构建任务，解析 PDF，保存 Markdown、图片和来源信息。已有 Markdown 可直接进入下一阶段。
5. agent 读取文档结构及必要片段，提交切片方案；脚本校验方案，按原文裁切。
6. agent 提供简介、关键词和导航内容；脚本组织参考文件、索引与来源记录。
7. 完成完整性校验后，将成品放入目标 Skill 目录，返回路径、构建状态和提示信息。
8. 用户明确提出发布需求时，提供打包和发布步骤引导。

CLI 默认非交互。询问由宿主 agent 完成，脚本接收明确参数并返回结构化结果；缺少必要配置时返回可处理的问题，不在终端阻塞等待输入。

项目目录由调用方明确提供；没有提供时，以调用工作目录为根。不能假定脚本所在目录就是用户项目，也不能把用户级工具目录的存在当作当前宿主 agent 的身份。

## 3. 运行模式

| 模式 | 判断与推进方式 | 模型配置 |
|---|---|---|
| 宿主 agent 模式，默认 | agent 决定语义切片和索引内容，CLI 校验并执行文件处理 | 复用宿主 agent 的判断能力，CLI 无需另配 LLM 密钥 |
| 自动模式 | 脚本调用用户配置的模型，完成相同的判断任务和流水线 | 用户提供可用的模型服务配置 |

两种模式共用阶段、任务状态、判断结果格式和校验逻辑。宿主 agent 模式通过结构化输入、结果提交和继续执行接口推进，不假定 CLI 可以直接调用宿主模型。

| 阶段 | 输入 | 输出 |
|---|---|---|
| 解析 | PDF 和解析配置，或已有 Markdown | 标准 Markdown、图片与原始来源信息 |
| 切片 | 文档结构、原文和切片方案 | 原文切片、层级关系与准确的来源范围 |
| 索引生成 | 切片与语义描述 | `SKILL.md`、参考文件和来源记录 |
| 校验与落盘 | 候选 Skill | 校验结果与正式 Skill 目录 |

- 首版支持按阶段执行、暂停、查看进度和从指定阶段继续。
- 允许显式切换运行模式，接着同一个任务继续；已完成且有效的结果不重复生成。
- 改变输入、配置或切片方案时，失效对应阶段及其下游结果。
- 不在失败后静默切换模型或运行模式。
- 各阶段独立选择模型或服务是后续能力。首版自动模式使用统一模型配置，解析器单独配置。

### 配置时机与隔离原则

模型配置按需设置，不作为安装或首次使用 Learnova CLI 的必填项。

| 使用场景 | 需要的构建服务配置 |
|---|---|
| 搜索、安装、升级社区 Skill | 无需 LLM 或 PDF 解析配置，继续使用原有 CLI 配置 |
| 宿主 agent 模式，输入已有 Markdown | 无需额外 LLM 或 PDF 解析配置 |
| 宿主 agent 模式，输入 PDF | 需要有效的解析服务配置，无需额外 LLM 配置 |
| 启动自动模式或中途切换为自动模式 | 检查 LLM 配置；仍需解析 PDF 时，再要求解析服务配置 |

用户可提前通过构建配置入口设置服务。已有有效配置直接复用；执行所需配置缺失时，由 agent 询问并允许保存。直接调用 CLI 时返回结构化问题，不阻塞等待终端输入。宿主 agent 模式不校验无关的 LLM 必填项。

- **业务配置独立。** 原有镜像、社区后端、安装层级和 agent 适配配置保持各自职责；LLM、解析器和构建参数由构建模块维护。
- **底层读写复用。** 复用现有 JSON 读写、原子替换和文件权限处理；构建模块负责自己的默认值、字段校验和配置解析，不再复制一套存储实现。
- **文件分开。** 建议使用独立的 `build-config.json`，不把模型必填项加入原有 `config.json`。具体存储位置和项目覆盖规则在实施规格中确定。
- **按命令加载。** 仅构建及其配置入口加载、校验构建配置，不在 `CliContext.build()` 中全局加载。构建配置缺失或损坏不得影响搜索、安装等原有命令。
- **服务分别校验。** LLM 与解析器各自持有服务地址和参数；原有 `backend_url` 仍表示社区后端地址，社区登录凭证不能当作模型或解析服务凭证。
- **密钥只做引用。** 配置仅记录密钥对应的环境变量名，执行时按需读取；配置查看、日志、任务快照及最终 Skill 不得输出或复制实际密钥。

新任务使用当次解析出的有效配置。续跑使用任务中保存的非敏感配置快照，修改已保存的默认配置不静默改变旧任务。用户显式为任务修改服务、模型或相关参数时，更新配置快照，重新判断受影响阶段及其下游缓存；单纯切换运行模式不丢弃已确认且仍有效的结果。

分层保持命令薄、逻辑集中：命令层只解释参数和返回结果；构建服务协调阶段；`core/` 放标题、范围、切片、校验等纯逻辑；解析和模型调用由适配层承接。网络调用沿用统一网络边界，状态采用原子写入。

构建服务统一管理任务文件和候选产物，正式目录替换复用安装引擎的事务方式。实现前须同步架构文档中的文件操作边界。文档解析不并入服务社区 `search/info/fetch` 的 `SkillSource` 协议。

### 建议模块划分

下列为职责和目录建议，不要求为每个阶段建立独立框架。

```text
skills/learnova-cli/
├── references/                 # agent 的构建流程与结果提交说明
└── scripts/
    ├── cli/commands/build.py    # 注册子命令、解释参数、返回 dict
    ├── build/
    │   ├── pipeline.py         # 阶段推进、生成判断请求、接收结果
    │   ├── config.py           # 按需加载、独立校验构建配置，复用公共读写
    │   ├── jobs.py             # 项目任务文件、产物与断点的统一 IO
    │   ├── parsers.py          # 远程/本地 MinerU 适配和可选 PDF 拆页
    │   ├── decisions.py        # 判断请求与自动模式模型调用适配
    │   └── prompts/            # 随安装包分发的自动模式判断模板
    ├── core/document.py        # 结构扫描、边界编号、原文位置映射
    ├── core/chunking.py        # 方案校验、范围切分、小块合并、层级构建
    ├── core/skill_build.py     # 索引模板、来源记录与完整性校验
    └── engine.py               # 复用或提取正式目录替换、失败回滚的事务操作
```

`core/` 处理文本和数据，不读写文件、不调用模型。`jobs.py` 管理构建文件，配置原子写入和网络请求复用现有公共能力，避免在命令层重复实现。

现有 `engine.install()` 要求安装版本信息。应抽出可复用的目录提交操作，分别由社区安装和本地构建提供各自的校验与来源记录；不能为复用安装函数给本地产物填虚构版本号。

运行时所需模板和 agent 指引必须在 `skills/learnova-cli/` 内，不能依赖未随安装分发的仓库 `docs/`。

### 阶段交互建议

关键接口是“领取待判断事项→提交判断结果”。两种模式只改变结果提供者，后续校验和执行保持一致。

```text
宿主 agent 提交结果 ─┐
                   ├─→ 同一结果校验 → 原文裁切/索引组装 → 同一任务断点
自动模型返回结果 ───┘
```

已提供以下操作，完整参数与输出契约见 CLI 规范和运行指南。

| 操作 | 职责 |
|---|---|
| `build create` | 校验输入与目标配置，创建任务，返回任务标识 |
| `build next` | 推进可确定执行的工作，返回待判断事项、暂停位置或完成结果 |
| `build read` | 按结构编号或来源范围读取原文，支持受限长度的分批读取 |
| `build submit` | 校验判断结果与原文版本，接受有效方案并保存进度 |
| `build run` | 自动模式循环执行同样的 next、判断和 submit，可停在指定阶段 |
| `build status` | 查询有效阶段、失败信息、待处理事项及产物路径 |

一次切片判断的请求示例如下（其余上下文字段省略）：

```json
{
  "task_id": "task-demo",
  "request_id": "request-demo",
  "document_revision": 1,
  "stage": "chunking",
  "status": "needs_input",
  "kind": "split_plan",
  "scope": {"id": "document", "start": 0, "end": 100},
  "allowed_boundaries": ["b0012", "b0024"]
}
```

agent 读取对应目录和原文后，提交同一请求标识、文档修订号以及选中的切点，例如 `splits: ["b0024"]`。脚本自行补齐该范围的首尾，校验边界和保护区间，再执行裁切。判断结果只描述方案或语义元数据，不携带重新生成的原文正文。

任务状态建议为 `pending`、`running`、`needs_input`、`paused`、`failed`、`completed`。等待 agent 结果是正常状态，按结构化成功结果返回；非法参数或无效提交按现有 `CliError` 处理，保留最近有效进度。文档修订号或请求标识过期时拒绝应用，避免旧回答覆盖新方案。

## 4. 产物与目录

```text
<project>/
├── .learnova/
│   └── builds/<task-id>/       # 解析全文、图片、方案、阶段结果与断点
└── .agents/
    └── skills/<skill-name>/   # 通过校验后可加载的成品
        ├── SKILL.md
        ├── references/        # 原文切片及其使用的图片
        └── .learnova-build.json
```

- `.agents/skills/` 是统一默认位置，不根据检测到的 agent 自动改成其他目录；显式输出配置优先。
- 默认使用项目级位置，通常不放用户级 Skill 目录。构建默认值独立于现有安装命令的默认层级。
- 目标已存在时默认报告冲突，显式要求覆盖才替换。失败不得损坏已有 Skill。
- 构建工作目录默认不纳入版本库。未完成产物留在任务目录，不作为正式 Skill 加载。
- 最终 Skill 包含索引、完整覆盖解析内容的原文切片、相关图片和来源记录。
- 原 PDF 保留原位置；完整解析全文和阶段文件留在构建工作目录，不默认打包进成品。
- 来源记录仅自动保存 `{"schema_version":2,"source":"local-build","version":null}`。输入指纹、范围、页码和图片清单留在私有构建任务，不进入最终来源记录。
- 来源记录不得包含密钥、本机绝对路径或其他不应随 Skill 分发的环境信息。

`.learnova-build.json` 为本设计采用的构建来源文件；具体字段及版本在实施规格中定义。原有 CLI 配置和认证文件保持原有用途，构建配置按第 3 节独立加载；构建任务只保存非敏感配置快照和必要引用，不复制密钥。

## 5. 完整性与恢复

### 切片实现构思

切片范围始终指向同一份标准 Markdown，使用左闭右开的字符范围 `[start, end)`。行号从范围计算；页码仅沿用解析器提供的映射。块内容直接取原文切片，避免反复 `strip()` 或重新拼接改变代码缩进和空白。

1. **建立结构表。** 扫描标题、段落及代码、公式、表格等结构，保存原文范围，给合法候选边界编号。结构不确定时保留更大的完整单元，不凭标题正则切入代码块。
2. **做章节粗切。** 给判断者目录、层级、长度统计和可追加读取的原文范围，由其选择章节边界及需要保护的区间。脚本验证编号存在、顺序正确、首尾覆盖且不穿越保护区间。
3. **逐块细分。** 对超过软阈值的大块，先尝试下级标题，再考虑合法的段落边界；每次只请求当前块的方案。保护标记随子范围继承。
4. **检查推进。** 子范围必须严格小于父范围。无有效切点、达到细分深度或不可拆单元超限时，保留原块并标注原因，避免无限递归或报告全部达标。
5. **处理小块。** 只在同一父级内尝试合并相邻小块；合并不能跨越已声明的章节或保护边界。合并后仍指向连续原文范围。
6. **生成树与参考。** 中间节点保存标题、层级和来源范围，叶子块生成参考文件。已确认范围的块标识在本次文档修订内保持稳定；方案变化后使相关索引失效。
7. **验证覆盖。** 按叶子范围排序，检查首尾、相邻边界及保护区间，确保可以重组标准 Markdown；再校验来源记录与图片引用。

token 数使用可配置的近似估算，只用于触发细分，不宣称是模型的精确 token 数。超大块按既定规则保留。无明显标题的文档可以由判断者选择段落边界，不强行按固定行数切开不可拆内容。

索引生成沿用上游“简介＋参考导航＋原文参考”的形式。判断者可读取标题及首、中、尾等代表片段，并按需继续阅读；不固定只截每块开头，也不把关键词当成正文摘要替代原文。`SKILL.md` 说明适用主题和如何查找参考；命名及元数据由脚本校验。

解析适配保留“提交→轮询→下载→整理”的流程。远程服务返回任务标识后即保存，恢复时优先继续查询已有任务。分批解析时，图片按批次隔离并改写相对引用，来源页码按分批偏移映射，避免同名图片覆盖。结果归集结束后才交给统一切片阶段。

### 内容完整性

- 完整保留解析结果，包括目录、附录、习题、答案和图片。不默认概括、删减或自动清理正文。
- 原文切片由确定性裁切产生；模型生成的简介和关键词与原文内容分开保存。
- 校验切片范围的连续性和覆盖关系，确保没有未声明的遗漏或重复。必要的文本规范化必须可追溯。
- 切片方案必须校验边界、顺序、范围和不可拆单元；无效方案返回纠正，不靠猜测执行。
- 代码、表格、完整证明等不可拆单元超过目标大小时，保留完整并标注超大块，允许 agent 按范围读取。
- 块大小是软目标，内容完整是硬要求；不能为了满足大小阈值丢失内容。
- 每个子块记录自己的实际原文范围，不能沿用父块的完整范围。
- `SKILL.md` 的参考链接和切片中的本地图片链接必须可解析，不留下缺失文件。

这里的完整性以解析结果为基准。解析服务本身的识别准确性不由结构校验保证；内容问答抽检另设可选验证步骤。

### 任务恢复

- 活动任务记录输入指纹、有效配置、阶段状态及产物引用。活动构建或显式 `resume --from` 时，方案或相关生成规则变化会重新判定缓存有效性。
- 活动构建检查私有断点对应文件实际存在且有效；完成状态仅代表构建历史，不检查交付目录、原始输入或新规则。普通 status/next/resume 不会重建已删除成品。
- 阶段失败保留已完成进度，返回错误位置和下一步所需输入。
- 断点原子写入；同一任务避免并发写入。重跑上游时使下游索引和语义缓存失效。
- 宿主 agent 与自动模式使用同一份任务状态；切换执行者不改变原文、切片标识和有效结果。
- 完整性校验未通过时，不把候选产物放入正式 Skill 目录；超大块等已允许情况作为提示返回。

## 6. 管理与发布

### 本地管理

沿用现有的目录扫描方式，不引入独立安装清单或数据库。

| 能力 | 本地构建产物的约定 |
|---|---|
| 列出 | 项目级 `list` 能识别，并显示本地构建来源；扫描仍包含其他来源的有效 Skill |
| 卸载 | 可显式卸载最终 Skill；不连带删除原 PDF 和构建任务 |
| 更新 | 直接编辑当前目录；需重新生成时显式 resume --from，保留冲突和 force 规则 |
| 社区升级 | 跳过本地构建产物，不能按同名社区条目覆盖 |

现有 `list`、`uninstall`、`upgrade` 默认操作用户级目录，`--project` 才操作当前项目级目录；本设计不顺带修改这些默认值。

项目级管理必须覆盖统一默认的 `.agents/skills/`，并合并所选 agent 的项目 Skill 根目录，对同一物理目录去重。不能因宿主使用其他目录而漏掉默认构建产物。自定义输出目录需要相应目录适配或显式配置，不递归搜索任意项目路径。

社区安装元数据保留目录名和版本，升级只处理社区来源。来源识别只读取 SKILL.md 和小记录，兼容旧 schema 1 本地来源记录而不校验其历史内容。本地构建产物不能仅凭与社区同名而升级，也不需要虚构社区版本号。旧安装记录和未声明来源的第三方包的兼容细则，在实施规格中明确。

用户编辑不改变记录的来源/已安装版本，不产生 dirty 状态或自动升级版本。内容的构建历史与当前副本的安装来源应区分。同一 Skill 后续经社区安装时，可按社区安装来源管理，同时保留文档构建的来源记录。

### 发布引导

- 构建成功默认不发布、不上传。
- 用户主动要求发布后，打包当前目录，允许用户编辑和新增内容，不与生成快照比较。检查 Skill 名称/描述、安全普通路径、有效的本地参考与图片链接；排除本地管理记录、私有任务、版本库和凭证文件。成品不存在则报可操作错误，不改变完成历史。
- 明确说明首版 CLI 尚未打通发布链路，不把引导完成描述成发布成功，也不调用尚未实现的命令冒充提交。

## 7. 首版验收

基础 CLI 保持 Python 标准库运行。文档构建允许按需安装可选依赖，依赖缺失只影响相关构建能力，不影响已有检索和安装；Python 依赖按项目约定使用 `uv` 管理。测试继续沿用现有 `unittest` 体系。

| 验收项 | 通过条件 |
|---|---|
| 能力说明 | 清楚标注只构建知识参考型 Skill，其他类型由 agent 借助外部能力处理 |
| 双运行模式 | 默认宿主 agent 推进；配置模型后可自动运行，且可显式切换后续跑同一任务 |
| 解析方式 | 远程和本地服务可配置；缺少有效配置时交由 agent 确认 |
| 按需配置 | 宿主 agent 处理 Markdown 不要求服务配置，自动模式检查 LLM 配置，解析 PDF 时检查解析配置 |
| 配置隔离 | 构建配置缺失或损坏不影响原有命令，服务参数分开校验，实际密钥不进入配置输出和任务产物 |
| 分阶段执行 | 能查看、执行和恢复指定阶段；不要求首版实现各阶段独立模型配置 |
| 输出位置 | 默认项目 `.agents/skills/<skill-name>/`，显式路径可覆盖，不依赖用户级工具检测 |
| 原文完整 | 切片覆盖解析内容、来源范围准确、不可拆超大块保留并标注 |
| 结构校验 | 元数据有效，参考文件和图片链接存在，失败不暴露不完整成品 |
| 恢复与覆盖 | 断点及文件一致，上游变化使下游失效，失败不损坏已有 Skill |
| 本地管理 | 扫描能识别构建来源，支持显式卸载，社区升级跳过本地产物 |
| 发布引导 | 默认不上传；用户要求时提供打包和引导，明确发布尚未集成 |

内容问答抽检是可选验证，不作为每次构建的强制成功条件。各阶段独立模型配置、其他类型 Skill 的专门构建、完整账号与发布链路不在首版范围。

### 建议实施顺序

1. 先用已有 Markdown 打通任务、结构表、方案提交和原文切片，验证宿主 agent 模式及完整性，不依赖真实解析或模型服务。
2. 完成索引、图片引用、来源记录和候选目录提交，打通一份可直接加载的项目级 Skill。
3. 接入远程和本地解析适配，补足分批 PDF、图片重名及服务任务恢复。
4. 接入自动模式，让其复用同一判断请求和结果提交接口，验证中途切换模式及阶段重跑。
5. 补齐本地构建来源管理、发布引导和运行时 agent 指引，再按首版验收表交付。

测试优先覆盖可验证的边界：保护区间不能被切开、叶子范围完整覆盖、子块来源准确、小块合并不越界、超大块明确标注、旧判断被拒绝、缺文件断点不会跳过、同名图片引用正确，以及两种模式对同一判断结果生成一致产物。配置测试覆盖宿主模式无需 LLM 配置、构建配置损坏不影响原有命令、默认配置变化不静默改变续跑任务、密钥引用不展开到输出。服务和模型使用假适配器验证，真实服务冒烟测试单独进行。

实施前，将命令、参数、JSON 字段和错误码细化到现有规范，并同步以下文件：

- [cli-spec.md](cli-spec.md)：构建流程、输出默认值、配置和管理行为。
- [architecture.md](architecture.md)：共享任务、阶段接口、模型适配和文件操作边界。
- [maintenance.md](maintenance.md)：新命令维护、错误码与验证要求。
- [AGENTS.md](../AGENTS.md)：可选依赖和项目级构建状态的适用边界。
- `skills/learnova-cli/SKILL.md` 及其运行时参考文件：包含 agent 使用指引。

本文位于仓库 `docs/`，用于设计与实施，不属于 `skills/learnova-cli/` 安装包中的 agent 指导文档。
